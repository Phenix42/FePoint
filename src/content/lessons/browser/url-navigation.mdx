## The journey in one sentence

Your browser turns a friendly address into network instructions, requests files from a server, and converts those files into an interactive page.

The stages overlap in real browsers, but this order is a useful first mental model:

1. Read the URL and check local knowledge.
2. Use DNS to find a network address.
3. Open or reuse a secure connection.
4. Send an HTTP request and inspect the response.
5. Parse HTML and CSS into browser models.
6. Calculate layout, paint pixels, and attach behaviour.

## What can change the journey?

A cache may already hold a fresh response. A service worker may answer locally. The server may redirect the browser to another address. Security policy may block a resource. Good debugging begins by checking which path this navigation actually used.

## A strong interview habit

State your assumptions before describing details. For example: “I’ll assume this is an HTTPS navigation, the page is not already open, and the browser may have cached DNS or assets.” This prevents absolute claims about a pipeline with many valid paths.
